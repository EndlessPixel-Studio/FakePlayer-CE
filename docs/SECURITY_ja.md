# セキュリティポリシー

[English](SECURITY.md) | [简体中文](SECURITY_zh.md) | [繁體中文](SECURITY_zh_TW.md) | 日本語

FakePlayer CE はサーバー上に実在のプレイヤーを生成し、任意で HTTP 管理 API も提供します。設定を誤ると、サーバーの制御権を第三者に渡すことになります。この文書では対応範囲、報告方法、安全な運用方法をまとめます。

## 対応バージョン

セキュリティ修正が入るのは最新のリリースのみです。古いビルドは更新されません。[GitHub Releases](https://github.com/EndlessPixel-Studio/FakePlayer-CE/releases) または [Hangar](https://hangar.papermc.io/EndlessPixel/FakePlayer-CE) から最新の `fp.buildN` に更新してください。

| ビルド | 対応 |
|---|---|
| 最新の `fp.buildN` | ✅ |
| それ以前のビルド | ❌ |

## 脆弱性の報告

**セキュリティ上の問題を公開 issue で報告しないでください。**

GitHub の非公開報告を使用してください。リポジトリの [Security タブ](https://github.com/EndlessPixel-Studio/FakePlayer-CE/security) → *Report a vulnerability* を開くと、メンテナだけが見られる advisory が作成されます。

次の情報を添えてください。

- プラグインのビルド（`/version FakePlayer-CE` または jar のファイル名）
- サーバー実装とバージョン（Paper / Purpur / Leaf / Folia、Minecraft のバージョン）
- 再現手順、期待した結果と実際の結果
- 関連する設定（token は伏せてください）とログの抜粋

受領の確認はできるだけ早く行います。ボランティアによるプロジェクトのため、数日お待ちください。修正が公開されたら、advisory とチェンジログで貢献を明記します。

## HTTP 管理 API

HTTP API は**既定で無効**で、各エンドポイントに個別のスイッチがあります。有効化する場合は次の点に注意してください。

### プラグイン側で行っている保護

| 保護 | 動作 |
|---|---|
| トークン認証 | `Authorization: Bearer <token>` のみ受け付けます。**`?token=` は非対応**です（クエリ文字列はプロキシログやブラウザ履歴に残るため）。`token` が空の場合は起動時にランダム値を生成し、コンソールへ出力します。 |
| ルーティング前の認証 | 認証はエンドポイントのスイッチより先に評価されるため、`401` / `403` から有効なエンドポイントを推測できません。 |
| 定数時間比較 | トークンは `MessageDigest.isEqual` で比較します（`String.equals` ではありません）。 |
| ログの秘匿 | 記録前にトークンを伏せ字にし、制御文字を置換します。 |
| レート制限 | 送信元 IP 単位で制限し、認証失敗が続くとロックします。 |
| Host / Origin 許可リスト | `allowed-hosts` は Host またはクロスオリジンの Origin が一致しないリクエストを拒否し、DNS rebinding を緩和します。 |
| キャッシュ禁止 | レスポンスに `Cache-Control: no-store` を付けます。 |

### 利用者側で必要な対応

- **TLS はありません。** 平文 HTTP です。`127.0.0.1` にバインドするか、TLS を終端するリバースプロキシの内側に置き、ファイアウォールでも送信元を制限してください。
- **`/cmd` は偽プレイヤーとしてコマンドを実行**し、その偽プレイヤーと同じ権限を持ちます。最も危険なエンドポイントです。不要なら `http-admin.interface.cmd` を無効にし、**偽プレイヤーを絶対に OP にしないでください**。偽プレイヤーを操作できる人は、その権限をそのまま得ます。
- **トークンは厳重に管理してください。** root パスワードと同様に扱い、スクリーンショット・ログ・公開リポジトリに露出したら直ちに再発行してください。
- **必要なエンドポイントだけを公開してください。** `http-admin.interface` 配下に個別スイッチがあるので、使わないものは無効にします。

### 加固チェックリスト

```yaml
http-admin:
  enabled: true
  host: 127.0.0.1          # ループバック、またはリバースプロキシの内側
  token: ""                # 空なら自動生成。十分に長いランダム値を設定するのが望ましい
  allowed-hosts: []        # プロキシ経由で公開する場合は公開ホスト名を指定
  rate-limit:
    requests-per-minute: 120
    auth-failures: 10
    lockout-seconds: 60
  interface:
    cmd: false             # 使わないエンドポイントは無効に
```

`localhost` の外へ公開する場合は、さらに:

- プロキシ層で TLS を終端し、プロキシのアドレスからのみ転送する
- トークンに加えてプロキシ側でも認証する（mTLS、Basic 認証、SSO ゲートウェイなど）
- プラグインログの `401` / `429` の繰り返しを監視する

## 対象範囲

対象: プラグイン本体（コマンド処理、HTTP API、`versions/` 配下の NMS モジュール、ログインプラグイン互換、アップデート確認、本リポジトリの Hangar / GitHub 公開ワークフロー）。

対象外: すでにサーバーが侵害されている前提の問題、意図的に偽プレイヤーへ OP を付与した場合、未対応のサーバーバージョンで `forced-execution: true` を使った場合、および文書どおりの機能利用による被害（例: `/fp cmd`）。
